# Source priority

> Approximate priority for Xbox 360 research. Higher = stronger authority. Lower is usable only with corroboration and explicit confidence downgrade.

1. Official Microsoft/Xbox public documentation + historical official docs (xbox.com archives, MSDN/XDK public pages, FCC filings).
2. Primary technical documentation (IBM developerWorks PowerPC/Xenon papers, ATI/Beyond3D architect interviews, NEC eDRAM notes where public).
3. Verifiable public source code (Xenia `xenia-project/xenia`, `xenia-canary`, libxenon, Free60 git, extraction tools with source).
4. Papers, theses, academic publications, conference talks with methodology.
5. Well-documented reverse-engineering (Free60 wiki with dumps/pseudocode, XenonLibrary hardware reference, ConsoleMods wiki with photos/PCB part numbers).
6. Specialist technical analysis with citations (Copetti “Xbox 360 Architecture — A Practical Analysis”, Ars Technica historic pieces, AnandTech/Beyond3D contemporary coverage).
7. Community documentation with evidence (forum threads with logs/dumps/photos, emulator compatibility notes).
8. Forums/discussions alone — only when they provide verifiable data; otherwise `UNCONFIRMED`.

## Rules

- Prefer direct file/commit/tag links on GitHub over homepage links.
- Record version/commit, date accessed, and what evidence each source provides.
- Follow reference chains: when a source cites another repo/paper/dump, follow it and record the chain.
- Never treat a random post as absolute authority.
